## 修复前确认的原因

1. **拇指依赖固定屏幕方向。** 旧代码根据 Left/Right 标签判断拇指尖在关节左边还是右边。掌心与手背翻转会改变这个关系。冻结录像中，清楚张开的掌心五指被算为 4，掌心的拇指加食指被算为 1。
2. **滑动门槛过高且依赖帧率。** 旧版要求平滑手腕位移超过 45 px/frame。`scripted` 诊断片段最大绝对平滑位移只有 37.31 px/frame，因此没有任何帧通过速度门槛；原版在两段录像中均发出 0 次滑动事件。
3. **当前帧数字与动作目标耦合。** 原版使用触发那一帧的手指数选择 loop；没有检测到手时立即清空计数和运动历史。数字短暂变为 0 会阻止触发，抖成其他非零数字则可能选错 loop。

## 最终改动

- **计数：** 拇指使用关节弯曲程度及相对于掌宽的距离。其余四指使用指尖越过关节、沿手掌自身轴线的伸展程度，替代固定的屏幕 y 方向。计算时校正画面宽高比例，不用 Left/Right 标签决定拇指是否伸出。
- **选择：** 数字保持约 120 ms 后成为目标；开始一段滑动时固定这个目标，运动中的原始计数抖动不会改变该次动作的 loop。
- **运动：** 采用实际采集时间和画面宽度归一化速度。默认 0.35 画面宽度/秒，60 ms 时间常数平滑；0.45 s 窗口内水平位移至少为画面宽度的 9%，持续至少 60 ms，并有多个移动采样点。方向、水平主导和轨迹一致性共同过滤单次跳点与抖动。
- **丢失：** 短暂丢失时最多保持目标 220 ms，界面显示 selection held。丢失期间不发指令；重新检测到手后重新积累运动，不把跨丢失窗口的位置跳变当成滑动。超过宽限时间则清空选择。
- **触发：** 每段持续滑动只发一次事件，并保留原有 0.8 s 冷却。改变方向或停止移动后可以准备下一段动作。
- **观测：** 日志区分 `raw_fingers` 与已选目标 `fingers`，记录是否处于 `tracking_held`；界面提示先稳定选定数字再滑动。`--swipe-threshold` 的单位已从 px/frame 改为画面宽度/秒。

实现依据中的坐标单位见 [MediaPipe Hands 官方说明](https://chuoling.github.io/mediapipe/solutions/hands.html#multi_hand_landmarks)。这是坐标约定的来源；本项目的判定规则及参数是本轮工程实现，不是官方提供的识别质量保证。

第一版候选曾对四指使用严格的三维关节角度，导致放松的三指姿态在 2/3 之间抖动；最终改为相对掌轴的伸展判断。中间候选的源文件与结果也已保留为 `after-main.py` 和 `results/r1-after/`，最终结果使用 `final-main.py` 和 `results/r1-final/`。

## 同一轮追加：音量误触修复

用户明确选择：“按 V 开关调音量，平时锁定音量（推荐，最明确）”。

- 默认锁定音量，普通伸手、选数字、滑动和收手均不调用音量调整。
- 按 `v` 进入调整，再按 `v` 锁定。进入时以当前音量和当前手指间距为起点，不跳到绝对距离对应的低音量。
- 间距按掌宽归一化，拉开增大、捏近减小；间距稳定约 150 ms 后确认更新。快速收手、掌宽急变或手部关键点接近/超出画面边缘时冻结调整。
- 一旦丢失跟踪，自动退出调整并保留最后确认的音量；恢复跟踪不会自动重新开启调音量。
- 音量模式中暂停 loop 滑动指令。界面显示 `VOLUME` 和锁定提示。
- 日志新增实际控制器音量、音量模式，以及源码 SHA-256 和 Python 环境信息。

旧版冻结录像中，idle 第 1580 帧（57.383 s）的拇指—食指距离为 0.030842，原映射将其设为 0；下一帧未检测到手。这是从原关键点和原公式推导的代码证据，不是旧现场日志中的音量测量；旧日志并未记录音量。推导数据保存在 `volume-before-derived.json`。

追加音量回归后共 33 项测试通过，覆盖默认锁定、进入时不跳零、相对调整、最后几帧误捏合后丢手、横向收手与掌宽急变、不同手部大小、画面边缘、调音量时阻止 loop 事件，以及普通 loop 操作保持音量。收据为 `recordings/repair-r1-evidence/tests-volume-final.txt`。

补修后的完整录像回放保存为 `results/r1-volume-final/`，与前面识别版分开留存。两段录像中控制器音量的最小值、最大值和最终值均为 0.8；滑动事件仍分别为 0 和 7，全部触发目标仍为 loop 1。主动音量模式包含 V 键状态，原始录像没有这些键盘事件，因此回放只验证默认锁定路径；主动调整的现场体验仍需单独复测。
